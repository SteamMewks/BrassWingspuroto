# Brass Wings 開発手順

## 着手

1. 起動用の `start_skill` が利用できる場合はセットアップを実施する。リポジトリ直下の `AGENTS.md` と `ARCHITECTURE.md` で構成と対象機能を確認し、DEVELOPMENT.md は必要な検証節だけを参照する。
2. `git status -sb`、履歴、リモートの対象ブランチを確認する。必要な既存変更を含む基点から作業ブランチを作り、ユーザーの未コミット作業を保持する。
3. ユーザーが期待する操作と終了状態を定め、該当するゲームモード、入力、描画、保存処理、テストを追う。小さな変更単位で実装し、判断にゲームルールの変更が必要ならその点を保留して報告する。

機能の識別子を rg で検索し、src/ の対象モジュールだけを開いて編集する。生成データ全文、配布HTML、docs/ の過去記録を通常の調査で開かない。全文の再読を避け、diff は必要なパス・範囲に絞る。

## 検証と再修正

変更後は node scripts/build.js を実行し、生成した単体HTMLを対象に `DEVELOPMENT.md` のコマンドを実行する。`smoke.cjs` は飛行・戦闘・進行、`terrain.cjs` は座標・地表、`visual.cjs` はChromiumでの操作と画面撮影を検証する。変更に特有の再現条件も試す。

撮影先を今回の検証専用に指定する。スマホ縦・横を先に開き、タイトル、基地待機、発進、通常飛行、一時停止、補給船待機、終了画面を比較する。文字やHUDの重なり、ボタンの位置・タッチ、機体と地表・海面の位置、画面遷移と状態表示を確認する。PCへの影響も確認する。地形変更時は変更地点まで移動し、同じ座標で見た目と接触判定を照合する。不具合があれば修正後のHTMLから再撮影する。自動判定、画像の目視、実機未検証を記録上で区別する。

## 納品

テスト結果は要約し、詳細ログは失敗時など必要な範囲だけ参照する。

生成物は編集元と同じコミットに含める。差分とテスト結果を確認して作業ブランチをPushし、Pull Requestを作成または更新する。関連PRに積み上げる場合は依存関係と提出先を明記する。

直接添付できる環境ではHTMLファイルを添付する。それ以外はPush先のブランチでファイルの存在と内容を確認し、GitHubのファイルURLと「Download raw file」での保存方法を案内する。HTML全文はチャットに貼らない。PRのURLとともに、実装・自動テスト・画像確認・HTMLの取得方法・残存問題と未検証事項を報告する。
