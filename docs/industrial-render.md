# 駅・工業地区の描画性能

計測の基点は main の d9c45e4。飛行中の入力、初期座標・機首方位、速度、シミュレーション時間刻みを固定し、測定の前後で同じ航路を再生した。Chromium、縦360×640・横640×360（DPR 2）、PC 1100×700（DPR 1）。各地点で8フレームのウォームアップ後に40フレームを取得した。1% Lowは短い標本での最長フレーム相当で、端末実機の持続性能を示す値ではない。

## 貨物駅の負荷調査

CDP CPUプロファイルには車輪と箱形部材の頂点生成、面変換、画像描画、GCが現れた。以前から地形は固定GPUバッファを使い、WebGL経路で地形三角形を毎フレーム生成する時間は発生しない。Canvas経路はクリップ・投影・奥行き順ソートを使う。比較用の別走行で描画APIを計数した。

|貨物駅・1フレーム平均|変更前|変更後|
|---|---:|---:|
|WebGL描画呼び出し|26|39|
|GPUへ提出した三角形|9,809|11,965|
|頂点バッファ転送量（B）|319,710|136,308|
|Canvas画像描画呼び出し|186|32|

静的設備の頂点転送は減少した。タイル単位でまとめて送るため、GPU呼び出し数と視界境界で扱う三角形数は増える。GPUタイマー拡張から有効な値を取得できなかった。CPU描画時間には非同期GPUの完了待ちは含まれない。

## 描画変更

- 線路、枕木、鉄橋、駅舎・構内設備、工場・倉庫を384 mタイルにまとめ、詳細度ごとのGPUバッファを再利用する。キャッシュは300エントリ・32 MiBを目安に古い順に破棄し、作戦原点の変更時に解放する。
- 画面の高さと対地高度を含む距離から詳細度を選ぶ。近景には4本のレール・枕木・車輪があり、遠景では各線の帯と列車・建物の輪郭を残す。列車・蒸気・船・灯台の灯火は動的に描画する。
- 河道を800 mタイルで索引化し、視界に入る区間を列挙する。遠方は水面を1区間にまとめ、近くの水しぶき・流れ・河口の色を保つ。
- 既存の6種類の樹木画像を1枚のテクスチャに格納し、同じ位置・大きさ・距離フェードでまとめて描画する。Canvas 2Dの経路も同梱し、WebGLを無効にしたChromiumで貨物駅上空を飛行した。
