# 世界地形の部分読み込みと描画計測

## PRの再レビュー

- [PR #10](https://github.com/SteamMewks/BrassWingspuroto/pull/10) は `b8169d9` で、鉄道の固定形状キャッシュ、河川の距離別簡略化、樹木の一括描画を導入。Vertex転送量は減ったが、地形は初期化時に全域をCPUで展開し、単一のWebGLバッファに常駐。報告されていた西域貨物駅の平均FPSは縦42.4→39.6、横36.5→38.9。
- [PR #11](https://github.com/SteamMewks/BrassWingspuroto/pull/11) は `cae3b7a` で、PR #10を基点に既存9水系と追加15水系を維持。貨物駅の報告値は縦41.2、横36.5 FPS。新規PRは `continental-tributaries` を基点とする。依存順は #10 → #11 → 本PR。

## タイルの展開と破棄

- 開発時のTINを2,048 m四方で符号化した。元の5 cm量子化座標と標高を維持し、区画境界を横断する三角形を隣接区画にも含める。描画は三角形の重心が属する区画から一度だけ送信し、衝突は参照位置の区画の同じ頂点で補間する。
- 通常は機体周辺と進行方向を優先し、速度に応じて最大1.6 kmを衝突用に先読みする。キャッシュにない地面は衝突照会時に同期展開する。描画は約6.2 kmと区画の境界余白までに絞り、先の地形は簡易海岸線と地表色で表示する。
- ミッションでは5 km四方に描画用4.2 kmと区画境界の余白を加える。出撃・帰投施設までの経路にも同じ描画用余白を適用する。施設が空域外にある場合は、飛行制限にも中心線の両側600 mの回廊を加える。通常ミッションの空域制限は従来どおり。
- CPU地形8 MiB、GPU地形16 MiB、鉄道GPU 8 MiBを上限の初期値として調整可能にした。距離または上限を超えるとキャッシュを破棄し、GPUは `deleteBuffer` を使う。タイトル帰還・ミッション切り替え時は地形・鉄道・河川・森林の展開キャッシュを消去する。
- 河川の24水系の流路と地図用データは保持し、距離計算・描画用の区画オブジェクトは使用時に展開する。列車運行・鉄橋・航空機と地表の判定は従来の処理を使う。
- 地形アーカイブの可逆圧縮後のHTMLは2,869,690 B（約2.74 MiB）。区画固有の境界頂点と事前生成データを内包し、外部ファイルとIndexedDBを必要としない。

## 施設と森林

基地の既存造成高、駅構内の既存軌道敷き、鉱山の切土造成を共有TINから利用する。鉄道の接地高度と市街地の道路・建物配置を開発時に確定し、起動時の高度照会を減らした。駅や基地の敷地では樹木候補を除外し、外周の緩衝帯では密度係数を0.18にした。自然林は256 m区画あたりの候補を100から49に、近傍キャッシュを49区画から25区画に減らした。表示距離は760 mから620 m。街路の一部と施設外周に高さ7～11 mの植栽を少量配置する。基地と駅は各2本までとし、舗装・線路・河川・建物・斜面に近い候補は見送る。中・遠距離の駅や住宅から細部と装飾を減らし、遠方の滑走路を一枚の帯で表示する。建物と基地を視錐台で絞り、地形と動的形状の頂点形式を28 Bから16 Bにした。

既存造成面を再利用できる施設を対象とした。全工場・市街地・農村に共通の新しい造成面を生成する工程と、森林密度そのもののオフライン事前計算は残っている。列車の経路と水系台帳は世界共通データとしてCPUに保持する。

## 同一条件の比較

ChromiumのSwiftShaderで、スマホ縦360×640・横640×360（各DPR 2）とPC 1100×700（DPR 1）を使用。比較元はPR #11の先端。各地点で同じ座標・進行方向・操作値を使用し、8フレームのウォームアップ後に40フレームを集計した。各欄は **前 → 後**。1% Lowは短いサンプルのため最も遅い1フレームによる近似。JSヒープは `performance.memory` の概算で、ブラウザ全体のRAMとは異なる。静的GPU容量はWebGLに確保した追跡対象バッファの合計で、ドライバとフレームバッファは含まない。

### 追加計測

専用の西域貨物駅プロファイルでは、描画呼び出し39→30、三角形11,965→11,092、頂点転送136,308→67,702 B/フレーム。GPUのタイマー拡張で実行時間を取得できなかった。初回描画時間には区画の展開・転送と他の描画処理が含まれる。同地点の180°旋回（32フレーム）では、p95が33.4→66.6 ms、最大CPU時間が27.9→16.8 ms、最大転送量が158,040→85,464 B。旋回時のフレーム落ちは残っている。GPU全体のメモリは未計測。

森林の保持数は西域貨物駅1,558→341本、大型中央駅1,157→141本、工業地区1,898→429本、西域平原飛行場1,862→272本。西域平原飛行場から中央大海へ移動した自動試験では、地形RAMの計測値48,669→0 B、地形GPUバッファ95,712→0 B。123,786枚の元の三角形にそれぞれ一つだけ描画担当区画があることを照合した。陸上作戦で展開した区画は全1,798区画中19区画。試験Cの空母出撃時は詳細地形を展開しなかった。

## 再現

```sh
export CHROMIUM_PATH=/usr/bin/chromium
node tests/world-areas.cjs
node tests/render-profile.cjs
node tests/render-survey.cjs /tmp/brass-current
BRASS_HTML=/path/to/pr-11/BrassWings-preview.html node tests/render-survey.cjs /tmp/brass-before
```

地形の再生成時は、従来の `tools/relief/survey.cjs` と `tools/relief/build.py` のあとに `node tools/relief/bake-rail.cjs` を実行し、編集元からプレビューをコピーする。
